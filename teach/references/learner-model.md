# A working learner model

Maintain a small record for the abilities relevant to the current goal. Model
observable tasks, not the learner's intelligence or a single overall level.
Separate what the learner reports from what the session demonstrates.

## Record the minimum useful evidence

For each active target, keep:

| Field | What to record |
| --- | --- |
| Target and conditions | The ability, task type, context, modality and permitted aids. |
| Independent evidence | What the learner attempted and demonstrated before target-specific help; identify the turn or task. |
| Supported evidence | The actual cue, example or explanation given, what changed, and which part the learner completed. |
| Working interpretation | One of the states below, with the scope and reason for uncertainty. |
| Difficulty or misconception | An observed error pattern or a tentative explanation to test. |
| Transfer and retention | Results on fresh tasks, reduced support and later attempts; distinguish these observations. |
| Next action | The task, support or review that would help learning or resolve an important uncertainty. |

Use short evidence notes, not a transcript after every turn. Update the affected
entry after each meaningful response. The learner should be able to understand
and correct the interpretation. Summarise changes at useful checkpoints without
interrupting every exercise to display a table.

## Interpret conservatively

| State | Meaning and consequence |
| --- | --- |
| Untested | No relevant observation. Select a probe when this ability matters. |
| Independent evidence | The learner succeeded without target-specific help under stated conditions. Confirm across varied tasks before treating performance as reliable. |
| Supported evidence | The learner made a meaningful contribution with assistance. This is a candidate for further work within the current ZPD. Record the help that worked. |
| Teaching needed | Success has not been demonstrated with the assistance tried. Change the task, support or prerequisite; do not declare a permanent limit. |
| Mixed or uncertain | Evidence conflicts or is confounded. Choose a discriminating probe instead of forcing a level. |

These are working descriptions, not calibrated test scores or mutually
exclusive facts about an entire concept. Preserve independent success on one
task alongside difficulty on another. Record the least support observed to work
in the particular sequence, not a supposed minimum the learner always requires.
Hints accumulate, so success after several hints is evidence about that whole
sequence.

Supported success without an independent baseline does not establish that the
task was beyond independent ability. Keep that boundary unknown until a suitable
unaided attempt is observed. Use both kinds of evidence when describing a task
as a candidate within the learner's current ZPD.

Do not promote an entry merely because the learner repeats a model answer or
selects the right option once. An explanation, a meaningful change of example
and later retrieval can provide additional evidence. Record confidence through
its basis, such as "one written sample; unfamiliar setting untested", rather
than inventing probabilities. Keep self-reported confidence separate.

## Preserve the conditions

- Distinguish recognition from recall, explanation from execution, and success
  in a familiar example from transfer. Avoid assuming that one implies another.
- Track modalities separately when they change the task. Written responses do
  not establish listening, pronunciation or spontaneous spoken performance.
- Record useful normal aids, such as a reference sheet or assistive technology.
  Independence means without target-specific tutoring under the agreed task
  conditions, not without all tools or accessibility support.
- Note answer exposure, hinting, translations, worked examples, repeated items
  or external assistance when known. Ask about aids only when it materially
  affects the interpretation; do not police the learner.
- Consider ambiguous wording, unfamiliar vocabulary, context, fatigue and
  incidental slips before inferring a missing concept. Probe around an error.
- If the teacher's answer or explanation was wrong, correct it and invalidate
  affected evidence. Do not retain a misconception label caused by bad teaching.

## Continue across sessions

Conversation context is enough for the current session. If the user asks to
retain progress, save a compact Markdown snapshot in their chosen destination.
Keep observations and current interpretations distinguishable; preserve useful
earlier evidence when revising a judgement. Record dates only when known.

Use this structure, scaled to the number of active targets:

```markdown
# Learning snapshot

Goal:
Session date or identifier:
Task conditions and aids:
Learner preferences:

| Target | Independent evidence | Support tried and response | Interpretation and uncertainty | Transfer or later review | Next action |
| --- | --- | --- | --- | --- | --- |

Unresolved questions:
Next useful review:
```

Populate it only from actual responses. Do not copy illustrative examples into
a real learner's record. If no persistent storage is available, provide a
copyable recap when continuity is requested and explain that it must be supplied
in a later session. Do not promise memory across harnesses.

On resuming, read the supplied snapshot, confirm the current goal and briefly
recheck a relevant ability before relying on old evidence. A saved state is a
hypothesis about present performance, not a guarantee that learning persisted.
